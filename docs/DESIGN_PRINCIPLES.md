# 设计原则

仓库提供两个独立进程：切流服务由平台（[AInfra](https://github.com/wqy0812/AInfra)）管理绑定，功能服务从本地文件读取模型适配与观测配置。平台持久化入口、目标、绑定和操作记录，切流服务只保留内存快照、在途计数和命令回执。功能服务可脱离平台及切流入口运行，其配置文件是功能参数的权威来源。时序、采集处理水位和看板归 [AInfra-monitor](https://github.com/wqy0812/AInfra-monitor)。

当前按一套部署管理，不预设其他部署环境；增加部署由用户另行说明。当前源码实现单入口切换及共享功能目标，见 [控制 v3](../MANAGEMENT.md)。本次拆分尚未表示部署完成，线上版本另行核验。

## 三个仓库共用的原则

1. **部署升级采用停机窗口，Router 切流在线完成。** 软件升级允许停机，不为升级零中断增加流程，也不执行版本回退。运行中的目标切换保持服务在线，已受理请求沿用原快照；在线切流所需的一致性保护单独评估。
2. **删除无消费者的退役实现。** 代码、专属测试、配置字段和示例在本套部署及当前调用方不再依赖后删除，历史从 Git 查。一次性迁移在本套部署完成并验收后清理，保留仍有用途的数据保护测试及迁移证据。
3. **一个事实只有一个权威归属。** 绑定和操作归平台数据库，功能参数归 proxy 本地文件；时序、采集与补算水位归监控。平台保存带摘要的功能配置观测副本，读回不自动改变入口快照。切流重启后等待平台恢复；功能服务重启后使用本地文件独立接流。
4. **关键流程测试覆盖生产路径。** 入口、控制和转发回归覆盖实际实现；纯计算逻辑保留单元测试，外部 Router 可用夹具模拟，真实链路验收按改动选择。
5. **发布身份是 Git commit 加构建产物摘要。** 共用一套发布工具，原始证据放忽略目录。
6. **文档标明实现状态。** 操作说明描述当前行为；设计方案区分已实现、已决定待实现和待验证内容，规则用正向表述。

新增模块、字段或流程前先说明实际消费者、解决的问题、可验证的失败场景，以及更简单的办法为何不足。部署流程考虑停机窗口，切流设计满足在线业务要求。

## 分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 命令入口 | `cmd/aigate-switch`、`cmd/aigate-proxy`、`service_main.go` | 独立启动参数、监听器、信号与优雅退出 |
| 切流 | `switch_service.go`、`runtime_control.go` | `/control/v3` 命令、目标快照、准入、测试占用、透明转发及有限 v2 测试兼容 |
| 功能服务 | `proxy_service.go` | 本地不可变配置、独立启动、脱敏状态、Router 观测目录 |
| 转发 | `gateway.go`、`adapter.go`、`routing.go`、`sse_*.go` | 模型发现、请求适配、SSE 观察与转发 |
| 观测 | `profile*.go`、`slow_requests.go`、`stream_incidents.go`、`*_diagnostics.go`、`runtime_retention.go` | 指标、画像、慢请求、流异常、传输诊断及保留 |
| 录放 | `traffic_recording.go`、`replay_*.go`、`cmd/aigate-replay` | 切流旁路录制、回放标记、平台控制的回放服务 |

## 网关规则

1. **流式优先。** 设计、性能优化和验收以 `stream: true` 链路为准；非流式保持现有兼容能力。
2. **状态分别归属。** 切流绑定只在内存中保存，重启由平台恢复；功能服务持有本地不可变配置，`--data-root` 只保存该 Router 的观测。入口切换不移动或重新标记观测历史。录制会话的意图和记录归平台，切流只执行单个窗口，会话状态不跨重启。
3. **功能参数通过文件修改并重启。** 监听地址、数据目录和切流控制密钥来自部署参数；平台只下发目标绑定，不发布功能参数。代理本地文件严格校验，状态剔除密钥、上游 header、环境变量名和 URL 查询参数。仅切流控制 API 和回放控制服务认证（各自独立密钥），业务与功能接口均不认证。
4. **已受理请求跑完自己的快照。** 切换只影响新请求；SSE 和等待模型发现、连接池的请求保持原快照直到结束。在线切流不等待全部旧请求排空，不主动中断或重放它们。
5. **准入锁内只改内存。** 磁盘和网络 I/O 不持有准入锁。切流绑定只在内存中保存；切流服务可由部署参数 `--record-root` 启用流量录制，录制由独立异步 worker 写入该目录，准入锁内不做磁盘 I/O，录制故障不影响转发。切流不打开其他观测存储。功能服务使用独立 Router 数据根目录和目录锁，避免并发写入及保留清理竞争。
6. **优先使用 Go 标准库。** 引入第三方库时说明收益、维护成本和依赖范围，按工作区要求执行 `go mod tidy`、`go mod vendor` 并提交依赖。构建与测试使用 `-mod=vendor`，离线验证设置 `GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local`。
7. **观测有界。** 每类观测都有解析上限、保留时长和容量上限，列表、搜索及指标只返回元数据与必要的短摘要；流异常诊断可在服务器有界留存完整请求、上游响应和位置时间线。平台按需通过独立只读接口分块查看已留存的请求与响应，固定文件快照、限制单块大小和读取并发；位置时间线仍仅供服务器排查。新增指标前确认 monitoring-api 或平台页面会消费它。
8. **按独立升级节奏维护接口。** 当前切流管理协议为 v3，固定旧执行镜像仅保留 v2 状态/命令查询和 test 动作；v2 counts 明确为 retiring_snapshots，不代表当前总负载。业务与主要观测接口保持路径，入站功能密钥已移除；本次拆分需要与平台、监控协调发布。后续新增可选字段或指标无需捆绑调用方发布。确需破坏兼容性时，单独安排网关与实际调用方的协调升级，核对固定旧执行镜像的接口依赖。平台与监控的配套改动可以在各自仓库提交并约定同一轮发布。
9. **远端生效独立确认。** 平台数据库事务不能保证网关同时生效。控制协议通过幂等处理、配置版本与实例身份防止重复或迟到命令覆盖新配置；超时后查询原结果。可以替换具体机制，不能以允许停机升级为理由删除在线切流的确认要求。

## 变更检查

- [ ] 能说明实际消费者、问题或可验证风险，以及简化方案的取舍
- [ ] 区分停机升级与在线切流，已受理请求保留原快照
- [ ] 绑定、功能配置与观测各有明确权威归属；切流快照未落盘，功能文件没有在线写入接口
- [ ] `openapi.json` 与接口一致，明确已部署调用方的兼容性及必要发布顺序
- [ ] 无消费者的退役实现已删除；迁移清理以本套部署完成并验收为准
- [ ] 关键流程测试覆盖生产路径，外部边界模拟与真实验收范围明确
- [ ] 文档区分已实现、待实现和待验证内容
