# 设计原则

网关是平台控制下的无状态执行面：转发 OpenAI 兼容请求与 SSE，发现模型，记录有界观测。配置、绑定、凭据和管理状态全部归平台（[AInfra](https://github.com/wqy0812/AInfra)）所有；时序存储和看板归 [AInfra-monitor](https://github.com/wqy0812/AInfra-monitor)。新设计先确认它属于执行面，再放进本仓库。

## 三个仓库共用的原则

1. **停机窗口是默认前提。** 不为零中断增加状态机、双写或回退路径。网关只服务本平台，交换 Router 也走停机窗口。
2. **退役即删除。** 下线的功能连同代码、专属测试、配置字段和示例一起删除，历史从 Git 查；不保留兼容分支或占位接口。
3. **一个事实只有一个归属。** 业务配置在平台数据库，时序在 VictoriaMetrics；网关重启后等待平台重新下发。
4. **测试走线上路径。** 默认测试覆盖生产入口实际使用的代码。
5. **发布身份是 Git commit 加构建产物摘要。** 共用一套发布工具，原始证据放忽略目录。
6. **文档只写现状，规则用正向表述。**

新增模块、字段或流程前先回答：线上谁消费它，它防住哪一次真实发生过的故障，停机窗口能否直接替代它。

## 分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `runtime_main.go` | 业务、控制、观测三个监听器，信号与优雅退出；只接受部署参数 |
| 控制 | `runtime_control.go`、`test_occupancy.go` | `/control/v2` 命令、快照代、准入、测试占用 |
| 转发 | `gateway.go`、`adapter.go`、`routing.go`、`sse_*.go` | 模型发现、请求适配、SSE 观察与转发 |
| 观测 | `profile*.go`、`slow_requests.go`、`stream_incidents.go`、`*_diagnostics.go`、`runtime_retention.go` | 指标、画像、慢请求、流异常、传输诊断及保留 |

## 网关规则

1. **流式优先。** 设计、性能优化和验收以 `stream: true` 链路为准；非流式保持现有兼容能力。
2. **网关只在内存中持有业务状态。** `--data-root` 只存观测数据；需要跨重启保留的内容放平台数据库，由平台下发。
3. **部署参数与运行配置分开。** 监听地址、数据目录、控制密钥来自启动参数或环境变量；平台只下发白名单内的运行字段。新增运行字段时，同时更新白名单、`openapi.json` 和平台的 `validate_runtime_settings`。
4. **已受理请求跑完自己的快照。** 切换只影响新请求；SSE 和等待模型发现、连接池的请求保持原快照直到结束。
5. **锁内只改内存。** 准入锁和命令锁保护内存状态，磁盘和网络 I/O 在锁外完成。
6. **只用 Go 标准库。** 构建与测试使用 `-mod=vendor` 离线运行；引入第三方库前先证明标准库无法实现。
7. **观测有界。** 每类观测都有解析上限、保留时长和容量上限，只保存元数据与必要的短摘要。新增指标前确认 monitoring-api 或平台页面会消费它。
8. **跨仓库接口成对修改。** `/control/v2`、`/metrics`、`/profile/v1/*` 的变更与平台或监控仓库的调用方在同一轮发布中完成。

## 变更检查

- [ ] 能说出线上消费方
- [ ] 没有为不停机新增状态或回退路径
- [ ] 业务状态没有落盘
- [ ] 跨仓库接口的另一侧和 `openapi.json` 已同步
- [ ] 被替换的代码、字段、示例配置和专属测试已在同一个 PR 删除
- [ ] 测试经过生产入口实际使用的代码
