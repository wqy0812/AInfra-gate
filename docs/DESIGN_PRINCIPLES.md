# 设计原则

网关是平台控制下的执行面：转发 OpenAI 兼容请求与 SSE，发现模型，记录有界观测。权威业务配置、绑定、业务凭据和操作记录归平台（[AInfra](https://github.com/wqy0812/AInfra)）管理；网关在内存中保存当前快照、在途计数和控制结果，部署参数由部署配置管理。时序、采集处理水位和看板归 [AInfra-monitor](https://github.com/wqy0812/AInfra-monitor)。

当前按一套部署管理，不预设其他部署环境；增加部署由用户另行说明。当前协议实现 Router 交换，见 [控制 v2](../MANAGEMENT.md)；以后可能支持直接切换 Router 指向，具体协议尚未设计。两者都遵循在线切流要求。

## 三个仓库共用的原则

1. **部署升级采用停机窗口，Router 切流在线完成。** 软件升级允许停机，不为升级零中断增加流程，也不执行版本回退。运行中的交换或目标切换保持服务在线，已受理请求沿用原快照；在线切流所需的一致性保护单独评估。
2. **删除无消费者的退役实现。** 代码、专属测试、配置字段和示例在本套部署及当前调用方不再依赖后删除，历史从 Git 查。一次性迁移在本套部署完成并验收后清理，保留仍有用途的数据保护测试及迁移证据。
3. **一个事实只有一个权威归属。** 业务配置和绑定归平台数据库；时序、采集与补算水位归监控；网关快照和在途计数保存在内存中。副本说明来源、版本和失效方式，网关重启后等待平台重新下发。
4. **关键流程测试覆盖生产路径。** 入口、控制和转发回归覆盖实际实现；纯计算逻辑保留单元测试，外部 Router 可用夹具模拟，真实链路验收按改动选择。
5. **发布身份是 Git commit 加构建产物摘要。** 共用一套发布工具，原始证据放忽略目录。
6. **文档标明实现状态。** 操作说明描述当前行为；设计方案区分已实现、已决定待实现和待验证内容，规则用正向表述。

新增模块、字段或流程前先说明实际消费者、解决的问题、可验证的失败场景，以及更简单的办法为何不足。部署流程考虑停机窗口，切流设计满足在线业务要求。

## 分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `runtime_main.go` | 业务、控制、观测三个监听器，信号与优雅退出；只接受部署参数 |
| 控制 | `runtime_control.go` | `/control/v2` 命令、快照代、准入、测试占用 |
| 转发 | `gateway.go`、`adapter.go`、`routing.go`、`sse_*.go` | 模型发现、请求适配、SSE 观察与转发 |
| 观测 | `profile*.go`、`slow_requests.go`、`stream_incidents.go`、`*_diagnostics.go`、`runtime_retention.go` | 指标、画像、慢请求、流异常、传输诊断及保留 |

## 网关规则

1. **流式优先。** 设计、性能优化和验收以 `stream: true` 链路为准；非流式保持现有兼容能力。
2. **网关只在内存中持有业务状态。** `--data-root` 只存观测数据；需要跨重启保留的业务配置、绑定和操作记录放平台数据库，由平台下发。
3. **部署参数与运行配置分开。** 监听地址、数据目录、控制密钥来自启动参数或环境变量；平台只下发白名单内的运行字段。新增字段更新网关白名单和 `openapi.json`，平台按已部署网关支持的字段更新 `validate_runtime_settings`，避免提前下发不支持的配置。
4. **已受理请求跑完自己的快照。** 切换只影响新请求；SSE 和等待模型发现、连接池的请求保持原快照直到结束。在线切流不等待全部旧请求排空，不主动中断或重放它们。
5. **准入锁内只改内存。** 磁盘和网络 I/O 不持有准入锁；命令锁可串行化观测存储打开和保留清理，避免并发操作同一目录。
6. **优先使用 Go 标准库。** 引入第三方库时说明收益、维护成本和依赖范围，按工作区要求执行 `go mod tidy`、`go mod vendor` 并提交依赖。构建与测试使用 `-mod=vendor`，离线验证设置 `GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local`。
7. **观测有界。** 每类观测都有解析上限、保留时长和容量上限，只保存元数据与必要的短摘要。新增指标前确认 monitoring-api 或平台页面会消费它。
8. **按独立升级节奏维护接口。** 网关低频升级，平台与监控更新默认兼容已部署的 `/control/v2`、业务与观测接口；新增可选字段或指标无需捆绑调用方发布。确需破坏兼容性时，单独安排网关与实际调用方的协调升级，核对固定旧执行镜像的接口依赖。平台与监控的配套改动可以在各自仓库提交并约定同一轮发布。
9. **远端生效独立确认。** 平台数据库事务不能保证网关同时生效。控制协议通过幂等处理、配置版本与实例身份防止重复或迟到命令覆盖新配置；超时后查询原结果。可以替换具体机制，不能以允许停机升级为理由删除在线切流的确认要求。

## 变更检查

- [ ] 能说明实际消费者、问题或可验证风险，以及简化方案的取舍
- [ ] 区分停机升级与在线切流，已受理请求保留原快照
- [ ] 状态有明确权威归属，网关业务状态未落盘
- [ ] `openapi.json` 与接口一致，明确已部署调用方的兼容性及必要发布顺序
- [ ] 无消费者的退役实现已删除；迁移清理以本套部署完成并验收为准
- [ ] 关键流程测试覆盖生产路径，外部边界模拟与真实验收范围明确
- [ ] 文档区分已实现、待实现和待验证内容
